Прокси размещён: `/var/www/ecad/gn_api.php`. DocumentRoot подтверждён HTTP/HTTPS-конфигурациями nginx для ecad.giulianovars.ru. Локальный server.js и конфигурации nginx/PHP-FPM не изменялись. Перед повторной заменой PHP сделан backup в закрытом каталоге `.config/gn-api`.

Ключ — 32 случайных байта (hex), хранится на ECAD в `/var/www/ecad/.config/gn-api/config.php`. Существующие правила nginx запрещают HTTP-доступ к скрытым каталогам; внешняя проверка конфигурации вернула 403. Каталог закрыт правами Unix, PHP-FPM-пользователю bitrix дан только проход к каталогу и чтение файла через ACL. Значение не записывается в этот документ. `gn_api.php` сначала проверяет GN_API_KEY из окружения, затем читает закрытый конфиг. При переносе на другой сервер защиту этого каталога обязательно сохранить.

Для обычной сборки Android Studio создан **TEMPORARY** файл `lib/gn_api_key.local.dart`, исключённый из git. `gn_api_config.dart` использует его как значение по умолчанию; `--dart-define` по-прежнему может переопределить ключ. На другом компьютере этот локальный файл нужно передать отдельно защищённым способом. В текущем этапе APK не собирался.

Проверено снаружи с обычной проверкой TLS: без ключа 401, неверный ключ 401, правильный ключ и случайный несуществующий логин — 200 и пустой JSON-массив. Рабочие UPDATE/INSERT/DELETE не выполнялись. Порт ECAD 127.0.0.1:13000 уже слушал и отвечал через /getuser; новый туннель не запускался. Происхождение и автозапуск существующего туннеля не менялись.

Для неизвестного endpoint выбран 400: существующий nginx перехватывает 404 и меняет ответ на HTML 200. Его глобальные error_page могут также заменять тела 5xx; конфигурация nginx в рамках задачи не менялась.

Ниже — исходные инструкции для повторного развёртывания; production уже использует описанный выше закрытый конфиг и локальный Dart-файл.

## Конфигурация

- Загрузить только `gn_api.php` в web root сайта ECAD после согласования доступа.
- PHP должен иметь расширение cURL.
- Задать `GN_API_KEY` в окружении процесса, обслуживающего PHP. Переменная в SSH-shell сама по себе не задаёт окружение PHP-FPM/Apache/IIS. Способ зависит от действующей конфигурации ECAD; для PHP-FPM это может быть `env[GN_API_KEY]` в конфигурации пула вне web root и репозитория.
- Использовать один случайный секрет для PHP и Flutter. Не добавлять его в git, URL, логи или опубликованные команды.
- Flutter читает ключ через `String.fromEnvironment('GN_API_KEY')`, по умолчанию из TEMPORARY локального Dart-файла. Без подходящего ключа запросы отклоняются прокси.
- Для сборки создать вне репозитория приватный JSON-файл вида `{"GN_API_KEY":"<секрет>"}` и выполнить:

```powershell
flutter build apk --debug --target-platform android-arm64 --dart-define-from-file="C:\private\gn-api.json"
```

Сборка проверки использует фиктивный ключ `LOCAL_COMPILE_CHECK_ONLY`; её нельзя считать готовой для подключения к production. Shared key попадает в приложение и не является неизвлекаемым секретом.

## Reverse SSH: Windows 172.16.4.104

ОС сервера подтверждена пользователем: Windows. Рабочая машина подготовки имеет адрес 172.16.2.50 — это другая машина.
На **172.16.4.104**, в PowerShell, сначала проверить:

```powershell
ssh -V
Test-NetConnection 127.0.0.1 -Port 3000
```

Если server.js не слушает loopback, команда ниже не сможет подключиться к нему. Не менять server.js автоматически.
При доступном OpenSSH и SSH-порте 22 выполнить, заменив ECAD_USER на реальную SSH-учётную запись:

```powershell
ssh.exe -N -T -p 22 -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -o ServerAliveCountMax=3 -R 127.0.0.1:13000:127.0.0.1:3000 ECAD_USER@ecad.giulianovars.ru
```

При другом SSH-порте заменить `22`. При необходимости добавить `-i` с путём к существующему приватному ключу. Не отключать проверку host key.
Оставить процесс работающим; Ctrl+C закрывает туннель. Keepalive обнаруживает обрыв, но автоматически SSH не перезапускает. Служба/автозапуск здесь не настраиваются.

На ECAD SSH должен разрешать remote TCP forwarding. До запуска проверить эффективную настройку `GatewayPorts`: требуется `no` (loopback) или `clientspecified` (учёт указанного адреса), но не `yes`, которое может принудительно открыть wildcard-интерфейс. Никаких правил публикации порта 3000 или 13000 в firewall не добавлять.

После запуска на ECAD (если Linux):

```sh
ss -ltn 'sport = :13000'
```

Ожидается `127.0.0.1:13000`; при `0.0.0.0:13000` или `[::]:13000` остановить SSH-туннель. PHP должен работать в том же сетевом пространстве, где слушает туннель; loopback внутри отдельного контейнера — другой адрес.

## Проверки без изменения рабочей БД

На ECAD проверить только GET; тело ответа не выводить, поскольку оно может содержать USERPASSWORD:

```sh
curl --silent --show-error --max-time 12 --output /dev/null --write-out 'HTTP %{http_code}\n' --get --data-urlencode 'nik=TEST_LOGIN' 'http://127.0.0.1:13000/getuser'
```

Это запрос `http://127.0.0.1:13000/getuser?nik=...`. Подставить тестовый логин. Код 200 проверяет транспорт, но не доказывает наличие сотрудника.
Проверку публичного PHP выполнять с X-GN-Api-Key, не выводя ключ и тело ответа в логи. Не включать curl `-v`/`--trace` с рабочим ключом.

PHP возвращает 400 для неизвестного endpoint, 405 для неверного метода, 401 при неверном ключе, 503 при отсутствии ключа/расширения, 502 при недоступном upstream и 504 после timeout. Полученный HTTP status и тело upstream передаются без JSON-перекодирования. Общий timeout — 10 секунд, connect timeout — 3 секунды. Автоматического retry нет: после timeout записи нельзя считать, что операция гарантированно не выполнилась.

## Приёмка после развёртывания

1. Собрать APK с рабочим ключом, совпадающим с ECAD.
2. Проверить вход, операции и поиск заказа с Wi-Fi фабрики и доступным интернетом телефона.
3. Отключить Wi-Fi, оставить 4G/5G.
4. Выйти из сохранённого профиля и выполнить вход заново, чтобы проверить именно /getuser.
5. Проверить загрузку операций и поиск заказа.
6. Выполнить операцию только на согласованной тестовой партии; подтвердить результат в учётной системе.
7. Подтвердить неизменность локального server.js.

Через новый публичный адрес нужен интернет. При Wi-Fi без интернета и отключённой мобильной сети доступа к ECAD не будет: локального fallback в этой минимальной реализации нет.
Тары/Брак и другие страницы сохраняют прежние адреса. Старые общие особенности приложения, включая глобальный HttpOverrides и обработку ошибок входа, не перерабатывались.
